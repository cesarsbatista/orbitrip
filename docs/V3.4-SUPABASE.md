# Orbitrip V3.4 — ativar contas e viagens compartilhadas

A V3.4 mantém o **modo local funcionando sem configuração externa**. Para ativar login por código de seis dígitos, convites, permissões e sincronização, execute as etapas abaixo.

## 1. Criar um projeto gratuito no Supabase

1. Acesse https://supabase.com/dashboard e entre na sua conta.
2. Clique em **New project**, escolha um nome como `Orbitrip`, uma senha de banco **forte e privada** e a região preferida.
3. Aguarde a criação do projeto. **Não há necessidade de contratar o Google Cloud ou o Apple Developer Program.** Os limites e as condições do plano gratuito do Supabase continuam aplicáveis.

## 2. Criar o banco de dados e as regras de segurança

No Supabase: **SQL Editor → New query**.

Copie e execute **todo o conteúdo** do arquivo [`supabase/schema.sql`](../supabase/schema.sql) deste repositório.

O SQL define:

- tabela de viagens com dados JSON e número de revisão;
- tabela de participantes e papéis `editor`/`viewer`;
- convites por código, uso único e validade de sete dias;
- RLS (Row Level Security), garantindo acesso por proprietário e participante;
- função de atualização com verificação de revisão, que **bloqueia sobrescritas silenciosas** quando duas pessoas editam a mesma versão;
- inscrição das tabelas na publicação Realtime.

**Importante:** receber atualizações em tempo real não significa mesclar automaticamente alterações simultâneas na mesma viagem. Havendo conflito, o aplicativo pede exportação do rascunho antes de recarregar.

## 3. Configurar o login com código de seis dígitos

1. Acesse **Authentication → Providers → Email** e mantenha o provedor de e-mail habilitado.
2. Em **Authentication → Email Templates**, edite o modelo de e-mail de acesso para incluir o token de seis dígitos usando a variável do Supabase `{{ .Token }}`. Não deixe apenas o link mágico: nosso formulário espera um código digitado.
3. Em **Authentication → URL Configuration**, defina o **Site URL** como o endereço HTTPS **real** em que a Orbitrip está publicada. Adicione URLs de redirecionamento equivalentes caso use mais de um endereço. Não presuma que o GitHub Pages está ativado: verifique em **GitHub → Settings → Pages**.
4. Em caso de atraso dos e-mails, consulte os limites e mensagens no painel Authentication. O envio padrão do Supabase tem restrições e pode exigir SMTP próprio para uso mais intenso.

## 4. Copiar as duas informações públicas de API

No painel Supabase, procure **Project Settings → API Keys** ou **Connect** (o nome pode variar).

Precisamos de:

- URL do projeto, no formato `https://...supabase.co`;
- **publishable key** ou chave pública legada `anon` (não é segredo de servidor).

Edite o arquivo [`config.js`](../config.js) no repositório:

```js
window.ORBITRIP_CONFIG = {
  supabaseUrl: "https://SEU-PROJETO.supabase.co",
  supabaseAnonKey: "SUA_CHAVE_PUBLICA"
};
```

**Nunca** cole no navegador, neste arquivo, no GitHub ou nesta conversa a chave `service_role`, `sb_secret_...`, senha de banco ou credenciais pessoais. O arquivo `config.js` é público; RLS e permissões do banco são a proteção dos dados.

## 5. Testar com duas contas

1. Faça backup JSON das suas viagens locais em **Dados e backup**.
2. Publique ou atualize o site após configurar o `config.js`.
3. Abra a Orbitrip. Digite seu e-mail e receba o código de seis dígitos.
4. Entre na conta e, em **Conta e compartilhamento**, selecione **Copiar minhas viagens para a nuvem**. Isso cria cópias e **não apaga** os dados locais.
5. Abra uma viagem e clique em **Compartilhar**. Gere um convite como **Editor**.
6. Envie o link `#convite=...` ou o código à sua esposa.
7. Ela entra com o e-mail dela e aceita o convite. A viagem aparece nas duas contas.
8. Edite uma atividade, aguarde a sincronização e confira o outro dispositivo.

## 6. Mapas e ícone

- O mapa interno continua usando **OpenStreetMap + Leaflet**.
- Os botões **Apple Maps** e **Google Maps** nas etapas abrem links públicos, sem APIs pagas.
- **Próxima parada** oferece acesso ao próximo evento futuro com endereço ou coordenadas.
- O manifesto da aplicação e os ícones ficam na raiz/`assets`; no iPhone, use Safari → Compartilhar → **Adicionar à Tela de Início**.

## 7. Limitações e recuperação de problemas

- O backend não funciona até concluir os passos 1–4.
- Em modo local, cada navegador conserva seu próprio armazenamento e **não compartilha** roteiros.
- Em modo nuvem, a edição simultânea da **mesma viagem** pode produzir conflito de revisão. O programa preserva um rascunho neste navegador quando possível e oferece exportação JSON; a mesclagem automática não está implementada.
- O armazenamento local é limitado, especialmente para fotografias em base64; mantenha backups.
- A sincronização depende de conexão à internet e do serviço Supabase.
- A estrutura de segurança foi implementada mas ainda requer **testes reais após configurar um projeto**.
- Contas gratuitas e cotas do Supabase podem mudar ou sofrer pausas por inatividade; confira o painel e as condições de uso.
